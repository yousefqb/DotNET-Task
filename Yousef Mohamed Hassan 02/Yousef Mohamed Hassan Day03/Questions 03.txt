The main difference between int.Parse and Convert.ToInt32 when handling null inputs comes down to exception handling versus default values:

int.Parse(null) throws an ArgumentNullException. It expects a valid string representation of an integer and immediately fails if the input is null.

Convert.ToInt32(null) returns 0. It safely handles null by returning the default value for a 32-bit integer.

2-

In user-facing applications, int.TryParse is strongly recommended over int.Parse primarily because users frequently enter unexpected, invalid, or empty input.

No Expensive Runtime Exceptions: int.Parse throws exceptions (FormatException, OverflowException, or ArgumentNullException) when input validation fails. Throwing and catching exceptions in .NET is resource-intensive and degrades performance, especially under heavy load. int.TryParse handles validation smoothly without throwing exceptions.

Prevents Application Crashes: If invalid input reaches int.Parse without an explicit try-catch block, the application will crash. int.TryParse guarantees safe execution regardless of what the user types.

Cleaner Control Flow: int.TryParse returns a simple bool (true if successful, false if not). This allows you to use straightforward if/else logic to show validation messages directly to the user instead of polluting your code with try-catch blocks for expected user errors.

Reference equality in .NET means that two object references point to the exact same memory location in the managed heap, rather than just having equivalent internal data (value equality).Understanding reference equality is critical in .NET for several reasons:Identity vs. Value: Reference equality determines whether two variables refer to the exact same instance. For example, two different Customer objects might have identical properties (same name, ID, address), but their reference equality is false because they occupy different memory addresses.Default Behavior for Reference Types: By default, all class instances (reference types) use reference equality for == and the inherited Equals() method from System.Object, unless explicitly overridden (like in System.String or record types).Performance: Checking reference equality (object.ReferenceEquals(a, b)) is an $O(1)$ memory address comparison. It is instantaneous compared to value equality, which requires comparing individual fields or properties.Fast-Path Optimization: Custom overrides of Equals() frequently use reference equality as a quick first check (if (object.ReferenceEquals(this, other)) return true;) to avoid running expensive property-by-property comparisons if both references already point to the same instance.Preventing Circular Dependency Crashes: Deep value-equality checks or serialization algorithms rely on reference tracking (checking if an object has already been visited by memory address) to prevent infinite loops when data structures contain circular references.Interpreting String Interning: Strings in .NET override Equals() for value comparison, but string interning allows separate literal strings with identical text to share the exact same reference in memory, making object.ReferenceEquals(str1, str2) return true.How to Check Reference EqualityIn C#, reference equality is explicitly evaluated using object.ReferenceEquals(a, b):Returns true only if both a and b point to the same memory location (or if both are null).Always returns false when comparing value types (like int or struct) because evaluating them boxes each value into a separate memory object.

Strings are immutable in C# (meaning their character values cannot be changed after creation) primarily for security, thread safety, performance, and memory optimization.

Thread Safety: Because string instances cannot be altered, multiple threads can safely read the same string simultaneously without requiring lock mechanisms or worrying about data corruption.

Memory Optimization (String Interning): Immutability allows the .NET CLR to reuse identical literal strings across an entire application. By storing only a single instance of a literal string in an internal pool (the Intern Pool), memory usage is drastically reduced.

Security: Strings are used extensively for sensitive operations, such as file paths, database connection strings, network addresses, and security tokens. If strings were mutable, a malicious method could alter a path or URL after it has already passed a security check.

Hash-Based Collections Integrity: Strings are frequently used as keys in hash tables and dictionaries. Immutability guarantees that a string's hash code (GetHashCode()) will never change after insertion, preventing subtle bugs where keys become unreachable.

Reference Sharing: Immutability makes it safe to pass strings into methods or assign them to multiple variables without making deep copies. Any operation that appears to modify a string (like .Replace() or .Substring()) actually creates a brand-new string object in memory.

6-

StringBuilder addresses the inefficiencies of string concatenation by avoiding repeated memory allocations and object creation.Because string is immutable, appending text using the + operator forces the .NET Garbage Collector to allocate a brand-new array in memory, copy all previous characters into it, and discard the old object. Performing this in a loop results in quadratic memory churn $O(n^2)$.StringBuilder solves this through three primary mechanics:Mutable Internal Array: StringBuilder maintains a contiguous, mutable internal char[] buffer. Calling .Append() simply writes new characters directly into this existing array without creating new heap objects.Dynamic Capacity Expansion: It allocates an internal array with a starting capacity (default is 16 characters). When the buffer becomes full, it automatically doubles its array size, reducing the total number of re-allocations from $n$ times to logarithmic $O(\log n)$ times.Garbage Collection Pressure Reduction: Because it modifies memory in place instead of creating thousands of temporary string objects, it drastically cuts down on Garbage Collection (GC) pauses and prevents memory fragmentation.Single Deferred Allocation: Only when you call .ToString() at the very end does StringBuilder allocate a final immutable string instance containing the completed text.



*******************************************************************************************************************
7-

StringBuilder is significantly faster for large-scale string modifications because it replaces repeated memory allocations with in-place buffer management.In-Place Mutation: Instead of allocating a new string object for every change (like string does), StringBuilder writes changes directly into an internal, expandable char[] buffer.Amortized $O(1)$ Appends: Rather than reallocating memory on every operation—which takes $O(n^2)$ time in a loop—StringBuilder doubles its internal array capacity only when full. This reduces array reallocations to a logarithmic rate ($O(\log n)$), resulting in an amortized $O(1)$ time complexity per append.Minimal Garbage Collection (GC) Overhead: Creating thousands of short-lived string instances triggers frequent, expensive Garbage Collection pauses. StringBuilder creates almost zero temporary objects, keeping memory clean and performance consistent.Optimized Final Output: It defers string creation until .ToString() is called, allocating a single, finalized string instance only once at the end of all modifications.

String Interpolation ($"...") is the most widely used string formatting method in modern C#. Introduced in C# 6.0, it has largely replaced older techniques like string.Format() and composite formatting.

Why String Interpolation is the Most Popular
Superior Readability and Developer Ergonomics: Variables and expressions are placed directly inside the string structure using curly braces (e.g., $"Hello {name}"). This makes code far easier to write, maintain, and scan compared to indexed placeholders (e.g., "Hello {0}", name).

Compile-Time Safety & Tooling Support: Because expressions are embedded directly within the string, the compiler verifies variable names, types, and formatting syntax at compile time. Visual Studio and IDEs provide immediate IntelliSense, syntax highlighting, and refactoring support.

Full Formatting Capabilities: It supports all standard formatting specifiers (like alignment, currency, and date formatting) directly inside the braces: $"Price: {price:C2}".

Zero Performance Penalty: The C# compiler translates string interpolation under the hood into string.Format() or highly optimized FormattableString / handler patterns (like InterpolatedStringHandler in modern .NET), providing optimal speed alongside clean syntax.

An Enum (short for Enumeration) is a distinct value type in C# that defines a set of named integral constants. Under the hood, an enum is backed by an integral type (by default, int). Instead of using magic numbers or plain strings, enums provide a type-safe way to work with a fixed set of predefined choices.

When is it Used?
Enums are used when a variable can only take one of a small, known, and fixed set of values.

Improving Code Readability: Replaces obscure numeric constants (e.g., status = 1) with human-readable names (e.g., status = OrderStatus.Shipped).

Enforcing Type Safety: Prevents developers from assigning invalid values to a variable at compile time.

State Machines & Options: Ideal for representational states (Days of the week, User Roles, Http Statuses, Order States).

Three Frequently Used Built-in Enums in .NET
System.DayOfWeek

Purpose: Represents the day of the week (Sunday, Monday, Tuesday, etc.).

Usage: Commonly used with DateTime.Now.DayOfWeek.

System.Net.HttpStatusCode

Purpose: Represents HTTP status code values returned by web APIs (OK = 200, NotFound = 404, InternalServerError = 500, etc.).

Usage: Extensively used in web applications and API integrations.

System.IO.FileMode

Purpose: Specifies how the operating system should open a file (Create, Open, Append, CreateNew, etc.).

Usage: Used with FileStream or StreamWriter operations.

3-

When to Use string
Use string for fixed, non-changing text or minimal operations where the overhead of instantiating StringBuilder is unnecessary.

Small, Fixed Concatenations: Combining 2 to 4 variables or literals (e.g., string fullName = firstName + " " + lastName;). The compiler automatically optimizes simple concatenations using string.Concat().

String Interpolation for Formatting: Building readable log messages or simple outputs (e.g., $"User {id} logged in at {DateTime.Now}").

Dictionary / HashSet Keys: Using text as keys in hash tables. Because string is immutable, its hash code (GetHashCode()) never changes, preventing data corruption.

Read-Only / Immutable Business Logic: Passing text around methods where you want to guarantee that the value cannot be modified in place by external code.

When to Use StringBuilder
Use StringBuilder for frequent, dynamic, or large-scale text modifications to prevent memory allocation churn and performance bottlenecks.

Concatenations Inside Loops: Appending or modifying text inside for, foreach, or while loops (e.g., reading lines from a file or building CSV records).

Building Complex Documents or Reports: Constructing dynamic HTML pages, JSON/XML strings, SQL queries, or large export files step-by-step.

Heavy Character Manipulation: Performing multiple inline modifications such as repeated .Replace(), .Insert(), or .Remove() calls on large text blocks.

Unknown Input Sizes at Runtime: When you cannot predict at compile time how many times a string will be modified.
