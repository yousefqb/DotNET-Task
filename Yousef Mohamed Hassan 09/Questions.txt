Ownership Level: Static members belong to the class itself, whereas instance members belong to a specific object instance created with new.

Memory Allocation: Only one copy of a static member exists in memory shared across all instances, while each object maintains its own independent copy of instance members.

Access Mechanism: Static members are accessed directly using the class name (ClassName.Member), whereas instance members require an object reference (objectInstance.Member).

Lifetime: Static members remain in memory for the application's entire lifetime; instance members live and die with their specific object instance.

No, not all operators can be overloaded in C#. The language intentionally restricts operator overloading to preserve core type safety and compiler predictability.

Overloadable Operators: Arithmetic (+, -, *, /), relational (==, !=, <, >), unary (++, --, !), and bitwise (&, |, ^).

Non-Overloadable Operators:

Assignment Operator (=): Overloading would break foundational memory copy and reference assignment semantics.

Member Access & Type Operators (., ?., is, as, typeof, sizeof): Reserved exclusively for the compiler and runtime engine to manage memory layout, type checking, and object navigation safely.

Short-Circuit Logical Operators (&&, ||): Cannot be overloaded directly to maintain short-circuit evaluation logic (overloaded implicitly via &, |, true, and false).

Instantiation Prevention: Static classes cannot be instantiated using the new keyword; therefore, instance constructors are logically redundant and explicitly prohibited by the C# compiler.

No Object State to Initialize: Instance constructors exist to allocate memory and initialize state for specific instance objects on the Heap. Static classes contain only static members associated with the type itself.

Sealed and Abstract Nature: Under the hood, the C# compiler emits static classes as both abstract and sealed, preventing both instantiation and derivation.

Static Constructor Alternative: Type-level initialization for static fields is handled exclusively by a single static constructor (static ClassName()), which runs automatically before the type is first accessed.

1. Behavior in Classes (Reference Types)
Default == Operator: Compares Reference Equality (checks whether both variables point to the exact same memory address).

Default Equals() Method: Performs reference equality by default, but is designed to be overridden to execute Value Equality comparison.

Polymorphic Behavior: Equals() supports runtime polymorphism (late binding), whereas == is an operator resolved at compile-time (early binding).

2. Behavior in Structs (Value Types)
Default Equals() Method: Compares Value Equality field-by-field out of the box (uses Reflection internally, which impacts performance).

Default == Operator: Not supported by default in structs; attempting to use it results in a compile-time error unless explicitly overloaded.

Overloading Requirement: To enable == for a struct, you must manually overload both == and != operators.

Yes, C# supports Generic Constraints using the where clause. Constraints restrict the type arguments that callers can supply when instantiating generic types or invoking generic methods.

Compile-Time Safety & Capability: Enforces strictly allowed types at compile-time and unlocks access to specific type members/methods inside the generic code.

Common Constraint Types:

where T : struct — Value type constraint.

where T : class — Reference type constraint.

where T : new() — Parameterless constructor requirement.

where T : InterfaceName — Must implement a specific interface.

where T : BaseClassName — Must inherit from a specific base class.

12-

Scope of Definition: Generic classes define type parameters (<T>) at the class level affecting all instance members, whereas generic methods define type parameters restricted solely to the method's own scope.

Type Assignment Timing: Generic classes require explicit type argument specification during object instantiation (new MyClass<int>()), while generic methods support Type Inference, allowing the compiler to infer types automatically from arguments (MyMethod(5)).

Class Context Independence: Generic methods can exist inside standard non-generic classes, enabling specialized generic behavior without making the entire class generic.

Granular Constraint Rules: Generic methods can declare individual type constraints independent of any surrounding class-level generic constraints.

Overriding Equals in the Department Class: How Accuracy Is Achieved
Improving accuracy when overriding the Equals method in the Department class depends on the following points:
Value Equality Instead of Reference Equality
The default behavior of Equals in classes compares whether the two objects point to the same location in memory (reference equality). When you override it, the comparison becomes based on the actual values of the properties (such as Id or Name) — this is known as value equality.
Successful Comparison with New Instances
When searching for a department using a new object new Department(6, "NETWORK") inside an array that contains the same values, the search function will be able to find the element and return true because the values match — instead of returning false due to the objects having different memory addresses.
Facilitating the Search Logic in the Related Class (Employee)
When comparing employees based on their departments, the Employee class calls the Equals method of Department. Having an accurate comparison for the department ensures that search, sorting, and filtering operations inside employee arrays work correctly.

Performance Protection (Avoids Reflection): Default value comparison across all struct fields requires Reflection, which introduces severe performance overhead and unnecessary memory boxing.

Ambiguous Equality Semantics: Structs can contain reference-type fields (e.g., arrays or objects); the compiler cannot safely assume whether callers want reference equality or deep value equality for those child fields.

Encourages Explicit Optimization: Forces developers to deliberately overload the == and != operators to write fast, direct, type-safe field comparisons tailored to the struct's requirements.

Consistency Requirement: Requiring explicit implementation ensures that if == is overloaded, !=, Equals(), and GetHashCode() are also overridden consistently.
